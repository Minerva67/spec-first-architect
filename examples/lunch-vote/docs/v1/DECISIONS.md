# DECISIONS：午饭投票

新决定追加在对应分组末尾，不改历史条目。推翻旧决定时新增一条并注明取代哪一条。

## 已定
| 编号 | 日期 | 决定 | 原因 | 谁定的 |
|---|---|---|---|---|
| D-01 | 2026-10-30 | 使用 TypeScript（strict）+ Next.js App Router，运行在 Node 运行时，前后端同仓 | 主流栈，文档多；契约可以前后端共用一份 | 需求方（开工沟通） |
| D-02 | 2026-10-30 | 所有实体主键用内部生成的 cuid 字符串；成员链接令牌与主键分开存 | 令牌可以重置而不动任何外键；主键不对外暴露含义 | 规划会话（技术层默认） |
| D-03 | 2026-10-30 | 投票的开放/截止状态和结果不落库，由 `deadlineAt`、当前时刻和票计算 | 派生值落库会和票数出现两处不一致 | 规划会话（技术层默认） |
| D-04 | 2026-10-30 | 截止时刻存 UTC 时刻 `deadlineAt`，另存团队本地日期 `pollDate`（YYYY-MM-DD）；团队表存 IANA 时区名 | 同时满足「按团队时间截止」和「每天一场」的唯一约束 | 规划会话（技术层默认） |
| D-05 | 2026-10-30 | 链接令牌格式为 `lv1_` 加 32 字节随机数的 base64url；库里只存 SHA-256 摘要 | 前缀给以后换格式留余地；数据库泄露不等于链接泄露 | 规划会话（技术层默认） |
| D-06 | 2026-10-30 | 定时推进由外部 cron 每分钟调用 `POST /api/cron/tick`，处理逻辑幂等 | 不依赖进程内定时器，换部署方式不改代码 | 规划会话（技术层默认） |
| D-07 | 2026-10-30 | 通知走 outbox 表，`(pollId, kind)` 唯一 | tick 重跑或并发时都不会重复发送 | 规划会话（技术层默认） |
| D-08 | 2026-10-30 | 权限判断只放在 services 层；路由层只负责从 cookie 取出身份 | 前端隐藏按钮不算权限控制 | 规划会话（技术层默认） |

## 假设
用户未确认，先按此执行。
| 编号 | 假设 | 依据 | 如果推翻要改什么 |
|---|---|---|---|
| A-01 | 一个部署只服务一个团队；表里仍保留 `teamId` 外键 | PRD 4「一个组」 | 多团队要加团队创建入口和跨团队隔离测试；表结构不用迁移 |
| A-02 | 持久化用 SQLite + Prisma，单实例部署 | 20 人以内，写入量极小 | 换 Postgres：改 Prisma provider 并重建迁移；domain 和 services 不动 |
| A-03 | 截止时刻 = 团队时区当天 11:30:00，到 11:30:00 整即视为已截止；团队时区默认 `Asia/Shanghai`，组长可在设置里改 | PRD 3.1 没写时区；PRD 4 提到分部同事在另一城市 | 改成按每人本地时间截止在规则上不成立（一场投票只能有一个截止时刻），要退回需求方重新定义 |
| A-04 | 页面上的截止时间一律按团队时区显示，并标注 UTC 偏移，例如「11:30（UTC+8）」 | 同 A-03 | 改成按查看者本地时间显示，只影响 T02 的格式函数和页面 |
| A-05 | 选项在第一票之前可改，有票之后锁定 | PRD 3.1「随时修改」会让已投的票指向被改掉的选项 | 坚持随时可改，就要定义被删选项上的票怎么办（作废并通知投票人），新增一个任务 |
| A-06 | 截止前成员可以改票，以最后一次为准；也可以在匿名与实名之间切换 | PRD 没写；「每人一票」理解为最终只计一票 | 改为不可改票，只影响 `castVote` 的一个分支和 AC-05 |
| A-07 | 结果和历史中，实名票显示成员名册上的名字，匿名票只计入票数 | PRD 3.4「谁投了什么」与 3.2 的匿名冲突 | 无 |
| A-08 | 通知渠道是组里群聊的群机器人入站 webhook，发纯文本；不做邮件和应用内推送 | PRD 3.2「在群聊中发一条提醒」 | 换渠道只需新增一个 Notifier 实现 |
| A-09 | 每个团队每天最多一场投票；当天截止之后不能再发起当天的投票 | PRD 3.1「发起当天的投票」 | 允许一天多场要去掉 `(teamId, pollDate)` 唯一约束，属于数据迁移 |
| A-10 | 截止时 0 票，公布「今天无人投票」并照常通知 | PRD 没写 | 无 |
| A-11 | 移除成员是软删除：不能再投票，历史里保留名字并标「已移出」 | PRD 没写；硬删除会让历史票的外键悬空 | 无 |
| A-12 | P-01、P-02、P-03 在拍板前按各自的推荐项执行 | 需求方不在场时不停工 | 见各条「阻塞哪些任务」 |
| A-13 | 组长也是成员，用 `role = leader` 区分；第一位组长由 setup 入口创建；本期只有一位组长，不做转让；组长丢了链接时在服务器上运行 `npm run leader:reset-link` 重置 | PRD 2 只有一个组长角色；没有登录体系，就需要一个服务器侧的找回方式 | 多位组长要放开 role 限制并补权限测试；表结构不变 |
| A-14 | 截止前今日视图只显示自己的选择和「已有 N 人投票」，不显示各选项票数和他人选择；历史只含已截止的投票 | PRD 没写；实时票数会带偏后投的人，也会提前暴露实名票 | 改为实时可见，只影响 `domain/redact.ts` 和今日视图 |
| A-15 | 「页面打开要快」定为：首次打开 `/` 传输的 JS 压缩后不超过 200 KB | PRD 4 没有可检验的标准；页面简单，这个预算宽松 | 只改 AC-27 的数字 |
| A-16 | 成员上限 50 人 | PRD 4 为 20 人以内，留出余量 | 只改一个常量 |
| A-17 | 过期通知不补发：截止后仍未发出的「已开始」、截止 24 小时后仍未发出的结果，标 `failed`（原因 `expired`） | 组长晚几天才配置 webhook 时，旧通知会一次性涌进群里 | 只影响 tick 的一个分支和 AC-26 |
