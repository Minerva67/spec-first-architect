# SPEC：午饭投票 v1

> 状态：草案（已过一轮独立复审）
> 权威顺序：DECISIONS 已定项 高于 本 SPEC（含第 4 节对原文冲突的处理）高于 ARCHITECTURE 高于 `source/PRD.md` 原文。PRD 是唯一的原始材料，没有原型和设计稿。
> 原始材料：`source/` 目录。本文不复述原始需求，只写工程需要而原文没有的内容。

## 1 目标

为一个 20 人以内的小组，把每天中午「吃什么」的群聊讨论换成一次限时投票。

成功一次 = 某天 11:30（团队时区）截止后，群里收到一条结果通知，且结果与当天的有效票一致。

PRD 5 的两条成功标准：「参与率超过 80%」用历史页每天显示的「参与人数 / 在册人数」衡量；「群里讨论减少」由需求方自行观察，系统不统计。

### 本期不做

- 注册、登录、密码、第三方登录
- 多团队（A-01）；一天多场投票（A-09）
- 多位组长、组长转让
- 提前结束投票、撤销投票、修改截止时刻
- 截止前催促未投票的人
- 成员自己添加选项；评论、点赞、表情
- 餐厅数据、地图、外卖下单
- 口味分析报表（PRD 3.4 的「了解口味」只靠历史列表满足）
- 邮件、短信、浏览器推送；页面实时刷新（WebSocket、轮询）
- 节假日日历：是否工作日由组长自己决定发不发
- 多语言、原生 App、小程序

## 4 原始材料的冲突与漏洞

C-01 属于「按原文流程跑不通」的一类，优先处理。C-12 至 C-15 是独立复审追加的。

| 编号 | 问题 | 本文采用的处理 | 决策编号 |
|---|---|---|---|
| C-01 | PRD 3.2 要求免登录、可匿名，又要求「每人只能投一票」。没有任何身份时无法识别同一个人，三条不能同时成立；而且群里发的是同一条链接 | 每位成员一条长期有效的专属链接，系统按成员去重；「匿名」指对其他人隐藏。群通知里附通用入口地址，成员第一次用专属链接打开后浏览器记住身份，之后从群里的链接直接进入 | P-01、A-12 |
| C-02 | PRD 3.1、3.3 的 11:30 没写时区；PRD 4 提到分部同事在另一城市 | 按团队时区计算和显示，默认 `Asia/Shanghai`，组长可改 | A-03、A-04 |
| C-03 | PRD 3.3「得票最多」没有定义平票 | 并列公布，通知列出全部并列项 | P-02、A-12 |
| C-04 | PRD 3.1「随时修改选项」会让已投的票指向被改掉的选项 | 第一票之前可改，之后锁定 | A-05 |
| C-05 | PRD 3.4「谁投了什么」与 3.2 的匿名冲突 | 只显示实名票的投票人；匿名票对任何人（含组长）只计票数 | A-07、P-03 |
| C-06 | PRD 2 有组长角色，但「不需要登录」时系统不知道谁是组长 | 组长也是成员，用 `role` 区分，管理权限挂在组长自己的专属链接上 | A-13 |
| C-07 | PRD 3.2、3.3 的「通知」没写渠道 | 群机器人 webhook，纯文本 | A-08 |
| C-08 | 一天能不能发起多场；截止之后能不能发起当天的 | 每天最多一场；截止后不能发起 | A-09 |
| C-09 | 截止时没有人投票，结果怎么写 | 公布「今天无人投票」并照常通知 | A-10 |
| C-10 | 投完能不能改 | 截止前可改，以最后一次为准 | A-06 |
| C-11 | 成员离组后，他的历史票怎么显示 | 软删除，历史保留名字并标「已移出」 | A-11 |
| C-12 | 截止前能不能看到各选项票数和别人投了什么，PRD 没写。看得到会带偏后投的人，也会提前暴露实名票 | 截止前只显示自己的选择和「已有 N 人投票」；历史只含已截止的投票 | A-14 |
| C-13 | PRD 4「页面打开要快」没有可检验的标准 | 定为：首次打开 `/` 传输的 JS 压缩后不超过 200 KB（AC-27） | A-15 |
| C-14 | PRD 3.2 群里发的是同一条链接。新成员、换手机或清了浏览器数据的成员从群链接进来时，系统不认识他 | 显示「请用组长发给你的专属链接打开一次」，不显示投票内容（AC-24） | P-01、A-12 |
| C-15 | PRD 2 只有一位组长，没写组长换人或丢了链接怎么办。按 C-06 的处理，组长丢链接后没有人能管理团队 | 本期只有一位组长，不做转让；组长丢链接时在服务器上运行脚本重置（AC-28） | A-13 |

## 5 验收

验证级别：一 单元测试、二 流程测试、三 构建、四 截图对照、五 真机手工。

| 编号 | 场景 | 通过标准 | 级别 | 对应任务 |
|---|---|---|---|---|
| AC-01 | 选项校验 | 2–6 个；去掉首尾空格后非空；每项不超过 30 字；去空格并忽略大小写后不重复。违反任一条返回 `INVALID_OPTIONS` | 一 | T03 |
| AC-02 | 截止时刻计算 | 团队时区 `Asia/Shanghai`、本地日期 2026-11-02 时，`deadlineAt` = `2026-11-02T03:30:00Z`；`America/New_York` 在 2026-10-31 时 = `2026-10-31T15:30:00Z`，在 2026-11-01（夏令时结束日）时 = `2026-11-01T16:30:00Z` | 一 | T02 |
| AC-03 | 截止边界 | `now` = `deadlineAt` 前 1 毫秒为开放；`now` = `deadlineAt` 起为已截止 | 一 | T02 |
| AC-04 | 截止时间显示 | 格式函数输出「11:30（UTC+8）」这类带偏移的文本 | 一 | T02 |
| AC-05 | 一人一票 | 同一成员投两次，库里只有一条票，内容为第二次；SQLite 实现上 `(pollId, memberId)` 唯一约束生效 | 二 | T05、T07 |
| AC-06 | 截止后投票 | 截止后投票返回 `POLL_CLOSED`，票数不变 | 二 | T05 |
| AC-07 | 发起限制 | 当天已有投票时返回 `POLL_EXISTS_TODAY`；当天已过截止时刻返回 `PAST_DEADLINE` | 二 | T05 |
| AC-08 | 选项锁定 | 第一票之前组长可改选项；有票之后返回 `OPTIONS_LOCKED` | 二 | T05、T13 |
| AC-09 | 结果未到 | 截止前请求结果返回 `RESULT_NOT_READY` | 二 | T05 |
| AC-10 | 计票 | 唯一最高 → `winner`；多个并列最高 → `tie` 并列出全部并列项；0 票 → `none` | 一 | T03 |
| AC-11 | 匿名裁剪 | 匿名票在结果、历史、任何 API 响应中都不带投票人，组长请求也一样 | 一、二 | T03、T05、T10 |
| AC-12 | 实名显示 | 实名票显示成员名册上的名字 | 二 | T05 |
| AC-13 | 权限 | 无令牌或令牌无效返回 `UNAUTHORIZED`；普通成员调用组长动作返回 `FORBIDDEN` | 二 | T05、T09、T10 |
| AC-14 | 专属链接 | 打开 `/m/<令牌>` 后写入 httpOnly cookie 并重定向到 `/`，地址栏不再含令牌；重置后旧令牌返回 `UNAUTHORIZED` | 二、四 | T09、T12 |
| AC-15 | 发起通知 | 发起后下一次 tick 发出一条「已开始」通知，文案含截止时间和 `APP_URL` 入口地址（文案见 ARCHITECTURE 7）；重复 tick 不重发 | 二 | T03、T06 |
| AC-16 | 结果通知 | 截止后第一次 tick 发出一条结果通知，winner、tie、none 三种文案各有用例，均含结果页地址；重复 tick 不重发 | 二 | T03、T06 |
| AC-17 | 通知失败 | webhook 失败时按退避重试，累计 5 次失败后标 `failed` 不再重试；失败不影响投票和结果页 | 二 | T06 |
| AC-18 | 历史 | 只含已截止的投票；按日期倒序，每页 30 条；每天显示结果、实名投票人、参与人数 / 在册人数 | 二 | T05、T14 |
| AC-19 | 移除成员 | 被移除的成员令牌失效；历史里名字保留并标「已移出」 | 二 | T05、T14 |
| AC-20 | 类型与构建 | `npm run typecheck`、`npm run lint`、`npm run build` 退出码为 0 | 三 | 每个任务 |
| AC-21 | 手机布局 | 375px 宽度下投票页、结果页、历史页、管理页无横向滚动，截图存入 `tests/e2e/screenshots/` | 四 | T12、T13、T14 |
| AC-22 | 真实群通知 | 在真实群里收到「已开始」和结果两条通知 | 五 | T16 |
| AC-23 | 端到端主流程 | 见下方步骤 | 四 | T15 |
| AC-24 | 未识别身份 | 没有 cookie 或 cookie 中的令牌无效时访问 `/`，显示「请用组长发给你的专属链接打开一次」，页面上没有任何投票内容 | 四 | T12 |
| AC-25 | 截止前可见范围 | 开放中的投票，今日视图只返回自己的选择和已投人数；不返回各选项票数和他人选择 | 二 | T05、T10 |
| AC-26 | 过期通知 | 截止后仍未发出的 `poll_opened`、截止 24 小时后仍未发出的 `poll_result`，标 `failed`（原因 `expired`），不再发送 | 二 | T06 |
| AC-27 | 页面体积 | 375px 视口首次打开 `/`，传输的 JS 压缩后总量不超过 200 KB | 四 | T15 |
| AC-28 | 组长找回链接 | 在服务器上运行 `npm run leader:reset-link` 输出新的组长链接，旧链接返回 `UNAUTHORIZED` | 二 | T09 |

AC-23 端到端步骤（Playwright，测试时钟固定在团队时区 2026-11-02 09:00）：

1. 用 setup 令牌创建团队和组长，拿到组长专属链接。
2. 组长添加三名成员，拿到三条专属链接。
3. 组长发起投票，选项为「面馆」「轻食」「外卖」。
4. 成员一实名投「面馆」，成员二匿名投「轻食」，成员三先投「外卖」再改投「面馆」。此时成员一的页面显示「已有 3 人投票」，看不到各选项票数。
5. 调用 tick，模拟 webhook 收到一条「已开始」通知。
6. 把测试时钟推到 11:30，调用 tick。
7. 结果页显示「面馆」2 票获胜、「轻食」1 票、「外卖」0 票；投票人只显示成员一和成员三的名字。
8. 模拟 webhook 收到第二条通知，内容含「面馆」。
9. 历史页第一行是 2026-11-02，参与人数显示 3 / 4。
