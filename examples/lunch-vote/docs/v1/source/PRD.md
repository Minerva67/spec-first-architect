# 午饭投票 PRD v0.3

> 文档状态：评审后修订版
> 适用范围：第一版（一个小组内部使用）

## 1 背景

我们组每天中午十一点多开始在群里讨论「今天吃什么」，消息一刷就是几十条，最后经常是谁先开口就听谁的，没开口的人也不好意思反对。

希望用一个轻量的网页把这件事收拢：组长每天出几个选项，大家投一下，到点自动出结果，群里不用再来回讨论。

## 2 角色

- **组长**：每天发起当天的投票，维护成员名单。
- **成员**：投票、查看结果、查看历史。

## 3 功能需求

### 3.1 发起投票

组长每个工作日上午发起当天的投票，填写 2–6 个选项，例如「楼下面馆」「轻食沙拉」「点外卖」。投票每天 11:30 截止。

发起后组长可以随时修改选项，比如临时得知某家店今天不营业。

### 3.2 投票

发起后，系统自动在组里的群聊中发一条提醒，附上投票链接。

成员点开链接即可投票，不需要注册或登录。成员可以自己选择匿名投票或实名投票，照顾到不想表态的同事。

每人只能投一票，不能重复投票，避免有人刷票。

### 3.3 截止与公布

到 11:30 自动截止，得票最多的选项就是当天的午饭。系统自动公布结果，并通知所有人。

### 3.4 历史

可以查看历史投票记录，包括每天的结果和谁投了什么，方便组长了解大家的口味，下次出选项时参考。

## 4 非功能要求

- 大部分人是在手机上点群里的链接打开，手机浏览器上要好用。
- 组里有 3 位同事常驻另一个城市的分部，也一起参与投票。
- 规模：一个组，20 人以内。
- 页面打开要快，不需要很复杂的设计。

## 5 成功标准

上线两周后：

- 群里中午关于吃什么的讨论消息明显减少；
- 每天参与投票的成员超过 80%。
