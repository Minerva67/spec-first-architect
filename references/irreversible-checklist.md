# 不可逆决策与外部前置清单

## 不可逆决策

上线后改动需要迁移数据或通知用户，所以开工前定。每项写明状态：已定、假设、待拍板。

| 项 | 要回答的问题 |
|---|---|
| 主键与标识 | 各实体的主键是什么格式；是否用内部标识而不是第三方标识做主键；对外暴露的标识有没有长度或字符限制 |
| 用户建模 | 用户是不是一等实体；登录身份和用户是否分开存；新业务数据是否用新集合加外键挂载 |
| 关系放在哪 | 多对多关系是否有独立的关系表；有没有把列表塞进单个文档导致无限增长 |
| 时间 | 存墙上时间、时间戳，还是两者都存；时区怎么处理；全天事件的结束时刻怎么定义 |
| 状态机 | 每个实体有哪些状态，哪些转换合法，哪些状态是派生的不落库 |
| 冗余计数 | 哪些计数做了冗余；由谁在什么事务里维护；真相来源是哪张表 |
| 权限 | 每类数据谁能读谁能写；判断放在服务端哪一层 |
| 钱 | 金额用什么单位和类型存；是否预留订单与支付流水的位置 |
| 凭证与签名 | 二维码、令牌的格式与版本前缀；密钥放在哪；换密钥时旧凭证怎么办 |
| 对外契约 | 接口的出入参、错误码；分享链接和场景参数的格式 |
| 可替换层 | 后端、存储、通知通道是否隔在接口后面，将来换供应商不动业务代码 |

## 外部前置

有等待周期，模型无法代办。尽早列给用户并行推进，任务清单里单独成组。

| 项 | 要确认的事 |
|---|---|
| 主体 | 个人还是公司，注册地，是否满足平台对主体的要求 |
| 备案与资质 | 需要哪些备案、许可，预计多久 |
| 平台类目与审核 | 类目是否匹配功能；哪些功能会触发额外审核 |
| 消息模板 | 通知模板是否要申请，字段和长度限制 |
| 关联账号 | 是否需要绑定开放平台、公众号、支付商户号，是否要求同一主体 |
| 隐私 | 隐私协议与权限声明；用到的敏感接口是否要单独申请 |
| 域名与证书 | 是否需要备案域名、配置合法域名 |
| 费用 | 云资源、第三方服务的计费方式与额度 |
